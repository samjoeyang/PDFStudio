# OCR 基线评测（CER）

用项目**真实的预处理逻辑 + 离线 Tesseract 引擎**跑样本，算出 **CER（字符错误率）**，
作为后续任何 OCR 优化的量化基线。没有这一步，调参都是盲调。

- CER = (替换 + 删除 + 插入) / 参考字符数，越低越好。
- 字符准确率 = 1 − CER（中文默认忽略空格后计算，更公平）。
- 引擎、tessdata、字体都与 app 同源、完全离线。

## 运行

```bash
npm run eval:ocr            # 跑评测（含后纠错前后对照），写 last-result.json
npm run eval:ocr:gen        # 重新生成合成样例图（含精确 ground truth 与降质样本）
node scripts/eval-ocr/gen-pdf-sample.mjs   # 重新生成图片型 PDF 样例

# 只评测 id 匹配正则的样本（结果写 last-result-only.json，不覆盖完整基线）
node scripts/eval-ocr/run.mjs --only '^hard-'      # 只跑真实感困难样本
node scripts/eval-ocr/run.mjs --only '^id-number$' # 只跑一个样本
```

`last-result.json` / `last-result-only.json` 是运行产物，每次评测会重新生成，
不参与应用构建，可随时清理。调参期使用的一次性诊断 / 网格探针脚本已清理，
实验结论保留在下方「当前基线」与「历史基线」章节。
评测器依赖 `@napi-rs/canvas` 与 `esbuild`，已声明在 devDependencies。

首次运行会加载中文模型，稍慢（约 30~60s）。
`run.mjs` 结尾会显式 `terminate()` 所有 Tesseract worker —— 否则结果写完后
Node 事件循环仍被占用，表现为「评测跑完却不结束」。

## 后纠错层（src/lib/ocr-correct.ts）

评测会同时计算**纠错前 → 纠错后**两套 CER。纠错层随 app 一起生效
（`ocr.ts` 与 `idcard.ts` 的输出都会过 `correctOcrText`）。

纠错策略是保守的：只替换「在正常简体中文里绝对不成词」的错拼。
表里的混淆对来自降质样本与真实证件照片的实测错字；加入新样本后，
对照 `last-result.json` 中的识别文本与参考文本找出错字类型，
把反复出现的形近字混淆补进 `ocr-correct.ts` 的 `WORD_FIXES` / `CONTEXT_RULES`，
再重跑评测验证 Δ。

## 样本结构

- `samples/manifest.json`：评测清单，每条：
  ```json
  { "id": "cn-paragraph", "file": "cn-paragraph.png",
    "lang": "chi+eng", "preprocess": "auto", "psm": "block",
    "ref": "cn-paragraph.ref.txt" }
  ```
  - `file`：样本文件，支持 PNG / JPG / PDF（PDF 取第 1 页栅格化）。
  - `lang`：`chi+eng` | `chi` | `eng`
  - `preprocess`：`auto` | `gray` | `binary` | `none`
  - `psm`：`block` | `column` | `auto` | `sparse`
  - `ref`：参考文本。可以是同目录的 `.ref.txt` 文件名，或直接写内联字符串。
  - `dpi`（可选）：仅 PDF 用，默认 350。

## 如何加入你自己的真实样本（关键）

当前 `samples/` 含干净渲染的合成样本、降质样本，以及 `hard-*` 五类真实感
退化样本（木纹背景、斜向阴影、倾斜、暗光低对比、密集小字）。三张真实身份证
照片因含个人信息已从仓库移除，**当前 18 个样本全部是合成样本**。新增样本请：

1. 把真实 PDF / 图片放进 `samples/`；
2. 准备对应 ground truth：新建 `<id>.ref.txt` 写入准确文本，
   或在 manifest 里用 `ref: "这里是准确文本"` 内联；
3. 在 `manifest.json` 追加一条；
4. 重新 `npm run eval:ocr`。

建议覆盖：模糊图、阴影翻拍、倾斜页、表格、手写、小字号。
样本越多、越贴近真实分布，基线越可信。

## 当前基线（2026-11-12，18 个合成样本）

| 阶段 | 整体 CER | 编辑距离 | 说明 |
|---|---|---|---|
| 纠偏缺陷修复后 | 2.92% | 39 / 1336 | 中间状态；此前阴影样本高达 92.31% / 100% |
| 候选维度扩展 + 打分修复 | 1.35% | 18 / 1336 | 补「原图 / 不纠偏 / 单栏」候选，压掉短乱码虚高分 |
| **中文标点与编码归一后** | **0.15%** | **2 / 1336** | 18 样本中 16 个 100%，仅 `cn-noisy` 剩 2 处标点 |

本轮四项改动：

1. **修复纠偏缺陷**（`src/lib/preprocess.ts`）：`estimateSkew()` 精细化循环的上界
   写成 `a <= bestAngle + 0.4`，而 `bestAngle` 在循环体内会被刷新，上界随之抬高，
   角度可一路爬到 **21.8°**（设计上限 ±5°），把带渐变背景的清晰文档整页旋成乱码。
   改为固定粗搜邻域，并对边界饱和（|angle| ≥ 4.9°）判定不可信、不旋转。
   阴影样本 CER 92.31% / 100% → **0.00% / 0.00%**。
2. **候选维度扩到三维**：预处理模式（新增 `none` 原图）× 是否纠偏 × 版面模式
   （新增 `column`），评测器 `run.mjs` 与应用 `recognizePages` 同步。
3. **打分加相对长度惩罚**（`src/lib/ocr-adaptive.ts`）：内容量不足最长候选 1/3 的
   候选扣 25 分，避免「4 字符乱码 + 虚高置信度」压过内容完整但 conf=0 的候选。
   `id-number-hard` 100% → **0.00%**。
4. **中文语境归一**（`src/lib/ocr-correct.ts`）：不成对弯引号删除、长编号后的
   多余逗号、`〈 ) :` → `（ ）：`、数字开头的编码串内 O→0 / I→1，
   以及 `工作骆`、`等发机关` 两个绝不成词的错拼。

**口径限制（重要）**：0.15% 是**合成样本**上的成绩，其中归一规则参考了这些样本的
残余错字，存在过拟合风险，不能直接当作真实扫描件的准确率。三张真实证件照已移除，
本轮改动**未在真实照片上复验**。调整权重或更换引擎前，先补入真实样本再跑回归。

另外修复了评测链路两处环境问题：macOS 下 `pdfjs` + `@napi-rs/canvas` 渲染 PDF
会触发原生段错误（退出码 139），改用系统 `sips` 按目标 DPI 栅格化；
`last-result.json` 现在会保存每个候选的文本片段，便于诊断打分选错。

## 历史基线：真实扫描件（2026-11-08，样本已移除，不可复现）

以下数据来自三张真实身份证照片，因含个人信息已从 `samples/` 移除，
保留作历史对照，**不能用当前 manifest 复现**。`real-baseline.json` 是其汇总。

`samples/real-*.jpg` 是三张真实身份证照片，ground truth 中的身份证号
已用 **MOD 11-2 校验码**验证过。

| 样本 | 上一版 CER | 当前 CER | 打分选中的候选 |
|---|---|---|---|
| real-merged（正反面合并扫描） | 31.30% | **3.48%** | 整图 / 二值化 / 1× |
| real-licailan（手机拍/木纹背景） | 36.62% | **16.90%** | 整图 / auto→二值化 / 1× |
| real-yangxiling（手机拍/木纹背景） | 21.62% | **21.62%** | 定位裁剪图 / 二值化 / 1× |
| **整体（按参考字符加权）** | **30.00%** | **12.31%** | 260 字符 / 编辑距离 78 → 32 |

全量 14 样本回归：**11 个合成样本 1.94% 完全不变**（516 字符 / 10 编辑距离），
全量整体 5.41%。收益全部来自真实照片，没有牺牲清晰输入。

**口径限制**：三张真实样本在 manifest 里使用 `psm: "column"`（单栏）——
带纹理的手机翻拍在该模式下明显优于应用默认的 `block`（整块文字）。
因此 12.31% 衡量的是「单栏 + 自适应」组合，不是默认开箱配置；
应用侧在「设置 → 版面分析」切到单栏即可复现（面板已给出场景提示）。

### 为什么有效：三张图的最优配置互不相同

「预处理模式 × 放大倍数 × 输入裁切」的网格实验证明，不存在单一「最佳全局配置」：

| 样本 | 二值化/1× | 灰度/1× | 原图/1× | 2× 放大 |
|---|---|---|---|---|
| merged | **3.48%** | 49.57% | 30.43% | 10.43%（变差） |
| licailan | **16.90%** | 36.62% | 38.03% | 46.48%（变差） |
| yangxiling | 67.57% | 41.89% | 40.54% | 33.78%（灰度，略好） |

而 `auto` 启发式只看光照不均度：对白底扫描件会选「原图」，对木纹照片又误选二值化；
且错版置信度可达 81%，「仅低置信度才重试」根本够不着。

### 落地的四项改动

1. **多候选自适应**（`src/lib/ocr-adaptive.ts`，纯函数）：auto 模式下补跑未命中的
   预处理路线，用「置信度 + 有效字符占比 + 汉字占比 + 身份证号 MOD 11-2 校验通过
   + 内容量 − 纹理乱码 − 无信息放大」打分；只有高出基线 3 分才切换，
   保证清晰输入不被「略高置信度但更差」的候选带偏。应用侧由
   `OcrSettings.adaptive` 控制（默认开，设置面板可关；关闭可让多页识别快约 2 倍）。
2. **证件定位裁剪作为额外候选**：评测器把「整图」和「定位裁剪图」都纳入候选。
   实测李彩兰那张用整图更好、杨希玲那张用裁剪图更好，让打分决定而非硬编码。
3. **整页大图不再插值放大**（`preprocess.ts`）：短边 ≥ 800px 时跳过 2×。
   双线性插值不增信息，反而放大背景纹理；三张真实照片的最优解全部是 1×。
   小条带样本（短边 < 800）仍按原逻辑放大，回归无变化。
4. 旧版「低置信度双向重试」被多候选取代（触发条件与打分口径已并入新逻辑）。

上表是 `scoreOcrCandidate()` 各权重的标定依据：调整权重前应重新做网格对照，
确认打分选中的候选确实对应低错误率，不要凭感觉改权重。

### 剩余瓶颈（历史结论，针对上述已移除的真实照片）

12.31% 仍不是「无需核对」：杨希玲那张还有整行丢失与地址错字，
`analyzePixels()` 在合并正反面图上仍 `fit=0.00`（现在定位失败会退回整图，
不再造成灾难）。再往上属于 Tesseract LSTM 的引擎天花板，需换现代检测+识别模型；
换引擎前后跑同一套 14 样本即可直接比出收益。

## 白名单（第三步）与低置信度重试

- `OcrSettings.whitelist` 透传 `tessedit_char_whitelist`。**实测结论：tesseract.js 的
  LSTM 引擎对白名单是"硬过滤"**——输入清晰时无增益（数字本来就读得准），
  输入稍差时会直接输出空串（置信度 0）。**不要单独依赖白名单**，关键字段请走
  字段级二次识别 + 格式校验（见 `idcard.ts` 的 `extractIdNumber`：
  auto → binary → 无白名单稀疏 逐级兜底 + MOD 11-2 校验码验证）。
- 旧版「低置信度双向重试」已由**多候选自适应**取代（见「当前基线」章节）：
  不再依赖 conf < 60 这类会漏判的触发条件（实测有错版置信度高达 81%），
  而是补跑未命中的路线后统一打分选优。当前 `id-number-hard` 两个白名单 / 非白名单
  条目均为 **0.00% CER**——单靠白名单曾长期停在 16.67%，是多候选路线救回的。
- 身份证号样本的校验位由 MOD 11-2 现算生成，号码合法；`id-number-hard`
  仍是"单路识别会整页失效"级别的压力样本，不要把它当作普通样本看。

## 实现要点

- `run.mjs` 在运行时用 esbuild 把 `src/lib/preprocess.ts`、`ocr-correct.ts`
  编译、把 `ocr-adaptive.ts` 与 `idcard-detect.ts` bundle 进来，
  保证评测用的是**线上同款**预处理 + 纠错 + 打分逻辑，不会脱节。
- 图像解码用 `@napi-rs/canvas`；PDF 在 macOS 上用系统 `sips` 按目标 DPI 栅格化
  （`pdfjs` + native canvas 在 Node 22 下 `page.render` 会段错误），其他平台回退 pdfjs。
- auto 模式下候选为「预处理模式（auto / none / binary / gray）× 是否纠偏
  × 版面模式（用户所选 + column）」，与应用 `recognizePages` 同一套维度；
  显式指定 `preprocess` 时退化为单路，保证对照实验口径不变。
- 结果（含每样本的识别文本、参考文本、各候选 key/置信/得分/文本片段）写入
  `last-result.json`，供前后回归对比与错字排查。
- 评测器与 `recognizePages` 的差异只有一处：评测器在 `detect: "card"`
  时会额外把「证件定位裁剪图」作为候选输入，用于覆盖证件场景；
  应用整页 OCR 路径本身不做证件裁剪（证件照片走 `IdCardPanel`）。
